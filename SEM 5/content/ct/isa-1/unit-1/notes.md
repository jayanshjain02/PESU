# **MODULE 1 — INTRODUCTION TO CLOUD COMPUTING**

## **1\. What is Cloud Computing?**

**Cloud Computing** is the delivery of computing services such as:

* Servers  
* Storage  
* Databases  
* Software  
* Networking

over the **Internet**.

Instead of purchasing and maintaining physical hardware, users access resources from cloud providers and generally pay based on usage.

### **Simple definition for exam**

> Cloud computing is the delivery of computing resources such as servers, storage, databases, software and networking over the Internet on an on-demand basis.

### **Examples**

* Google Drive → Cloud storage  
* Google Docs → Cloud software  
* AWS → Cloud infrastructure  
* Microsoft Azure → Cloud services  
* Google Cloud → Cloud services

---

## **2\. NIST Definition**

According to **NIST**, cloud computing provides:

> On-demand network access to a shared pool of configurable computing resources with minimal management effort.

Examples of resources:

* Networks  
* Servers  
* Storage  
* Applications  
* Services

### **Electricity analogy**

Cloud computing is similar to **electricity**.

We do not own a power plant.

We simply:

**Use electricity → Pay according to consumption**

Similarly:

**Use cloud resources → Pay according to usage**

# **MODULE 2 — NEED, EVOLUTION AND BASIC DEVELOPMENT OF CLOUD COMPUTING**

## **1\. Need for Cloud Computing**

Traditional IT requires organizations to purchase:

* Servers  
* Storage devices  
* Networking equipment  
* Software licenses

Organizations must also handle:

* Installation  
* Maintenance  
* Upgrades  
* Security  
* Operational costs

Cloud computing reduces these requirements by providing resources through the Internet.

---

## **2\. Major Reasons for Cloud Adoption**

### **1\. Reduced Infrastructure Cost**

Organizations do not need to purchase large amounts of physical hardware.

### **2\. Faster Deployment**

Resources can be created quickly.

### **3\. Remote Accessibility**

Users can access resources from different locations.

### **4\. Scalability**

Resources can be increased or decreased according to demand.

### **5\. Business Continuity**

Cloud services help organizations continue operations.

### **6\. Disaster Recovery**

Cloud backup can help recover data after failures.

---

## **3\. Evolution of Computing**

Mainframe Computing  
        ↓  
Personal Computers  
        ↓  
Client-Server Architecture  
        ↓  
Internet Computing  
        ↓  
Virtualization  
        ↓  
Cloud Computing

### **Mainframe Computing**

Centralized computers served many users.

### **Personal Computers**

Computing moved closer to individual users.

### **Client-Server**

Clients requested services from centralized servers.

### **Internet Computing**

Applications and resources became accessible over networks.

### **Virtualization**

One physical machine could run multiple virtual machines.

### **Cloud Computing**

Computing resources became available on demand through the Internet.

## **4\. Virtualization**

**Virtualization** allows multiple virtual machines or environments to run on a single physical server.

It is an important technology behind cloud computing.

# **MODULE 4 — CLOUD COMPUTING ECOSYSTEM**

It includes:

* Cloud Service Provider  
* Cloud Consumer

* Cloud Auditor  
* Cloud Carrier

# **MODULE 5 — CHARACTERISTICS OF CLOUD COMPUTING**

The PDF follows the **five essential NIST characteristics**.

## **1\. On-Demand Self-Service**

Users can automatically provision resources without contacting the provider.

**Example:** Creating a virtual machine in Azure.

---

## **2\. Broad Network Access**

Cloud services are available over networks using standard mechanisms.

They can be accessed through:

* Smartphones  
* Tablets  
* Laptops  
* PCs

**Example:** Google Drive.

---

## **3\. Resource Pooling**

Cloud provider resources are pooled and shared among multiple customers.

This is called a **multi-tenant model**.

         Cloud Infrastructure  
        /        |        \\  
   User A     User B     User C

Each customer's data remains separate and secure.

---

## **4\. Rapid Elasticity**

Resources can automatically scale up or down according to demand.

**Example:**

Normal Traffic  
     ↓  
High Traffic  
     ↓  
Resources Increase  
     ↓  
Traffic Falls  
     ↓  
Resources Decrease  
---

## **5\. Measured Service**

Cloud usage is measured and monitored.

Users are charged according to consumption.

Examples:

* Storage used  
* Compute used  
* Network usage

---

## **Easy Memory Trick**

### **O-B-R-R-M**

**O** → On-Demand Self-Service  
**B** → Broad Network Access  
**R** → Resource Pooling  
**R** → Rapid Elasticity  
**M** → Measured Service

# **MODULE 8 — CLOUD DEPLOYMENT MODELS**

Cloud deployment models describe **how cloud infrastructure is deployed, managed, owned and accessed**. The PDF identifies four NIST deployment models.

## **Four Deployment Models**

1. Public Cloud  
2. Private Cloud  
3. Community Cloud  
4. Hybrid Cloud

---

## **1\. Public Cloud**

Infrastructure is owned and managed by a third-party cloud provider.

Resources are shared by multiple customers.

### **Advantages**

* Low initial investment  
* Easy deployment  
* Automatic updates  
* Global accessibility  
* High scalability

### **Limitations**

* Less infrastructure control  
* Shared resources  
* May not satisfy strict regulatory requirements

### **Examples**

* AWS  
* Microsoft Azure  
* Google Cloud

---

## **2\. Private Cloud**

A private cloud is dedicated to **one organization**.

It may be:

* On-premises  
* Hosted by a third-party provider

### **Advantages**

* High security  
* Better compliance  
* Greater control  
* Improved privacy  
* Customization

### **Limitations**

* Higher cost  
* Requires skilled IT staff  
* Limited scalability compared with public cloud

### **Examples**

* Banking  
* Defence  
* Government  
* Large hospitals

---

## **3\. Community Cloud**

A community cloud is shared by multiple organizations having similar:

* Goals  
* Security requirements  
* Regulatory requirements

### **Advantages**

* Lower cost than private cloud  
* Better collaboration  
* Shared infrastructure  
* Improved compliance

### **Limitations**

* Limited flexibility  
* Shared governance  
* Complex management

### **Examples**

* Universities  
* Government departments  
* Healthcare organizations  
* Research institutions

---

## **4\. Hybrid Cloud**

Hybrid cloud combines two or more cloud environments, usually:

**Private \+ Public**

Sensitive data can remain in the private cloud while less-sensitive workloads use the public cloud.

### **Advantages**

* Flexibility  
* Better disaster recovery  
* Cost optimization  
* Increased scalability  
* Business continuity

### **Limitations**

* Complex integration  
* Higher management effort  
* Security configuration challenges

---

## **Easy Comparison**

| Model | Users | Main Feature |
| ----- | ----- | ----- |
| Public | Many customers | Shared |
| Private | One organization | Dedicated |
| Community | Similar organizations | Shared purpose |
| Hybrid | Combination | Flexible |

# **MODULE 9 — CLOUD SERVICE MODELS: IaaS, PaaS AND SaaS**

The three primary service models in the PDF are:

* **IaaS**  
* **PaaS**  
* **SaaS**

---

# **1\. IaaS — Infrastructure as a Service**

IaaS provides virtualized computing resources over the Internet.

### **Provides**

* Virtual machines  
* Storage  
* Networking  
* Operating systems  
* Firewalls  
* Load balancers

The **provider manages physical infrastructure**, while the customer manages the operating system, middleware, applications and data.

### **Advantages**

* High flexibility  
* High control  
* Easy scalability  
* Cost-effective  
* Useful for development/testing

### **Limitations**

* Requires technical expertise  
* Customer manages OS and applications

### **Examples**

* AWS EC2  
* Azure Virtual Machines  
* Google Cloud Compute Engine

---

# **2\. PaaS — Platform as a Service**

PaaS provides a complete development platform.

### **Provides**

* Operating system  
* Programming tools  
* Databases  
* Middleware  
* Runtime environment

Developers focus on **writing and deploying applications** rather than managing infrastructure.

### **Advantages**

* Faster development  
* Reduced maintenance  
* Automatic updates  
* Built-in development tools  
* Collaboration

### **Limitations**

* Less control over infrastructure  
* Possible vendor lock-in

### **Examples**

* Google App Engine  
* Microsoft Azure App  
* Salesforce Platform

---

# **3\. SaaS — Software as a Service**

SaaS provides **ready-to-use software applications over the Internet**.

Users simply sign in and use the software.

The provider manages:

* Infrastructure  
* Operating system  
* Software  
* Updates  
* Security  
* Maintenance

### **Advantages**

* Easy to use  
* No installation  
* Automatic updates  
* Anywhere access

### **Limitations**

* Limited customization  
* Internet required  
* Less software configuration control  
* Subscription-based pricing

### **Examples**

* Google Workspace  
* Microsoft 365  
* Zoom  
* Dropbox

---

# **IaaS vs PaaS vs SaaS**

| Feature | IaaS | PaaS | SaaS |
| ----- | ----- | ----- | ----- |
| Infrastructure | Provider | Provider | Provider |
| OS | Customer | Provider | Provider |
| Runtime | Customer | Provider | Provider |
| Applications | Customer | Customer | Provider |
| Control | High | Medium | Low |
| Ease of use | Medium | High | Very High |
| Main users | IT Teams | Developers | End Users |

### **Easy Memory Trick**

**IaaS → Infrastructure**

**PaaS → Platform**

**SaaS → Software**

---

## **Layered Architecture**

       End Users  
           ↑  
      Applications  
           ↑  
       Middleware  
           ↑  
    Runtime Environment  
           ↑  
      Operating System  
           ↑  
       Virtualization  
           ↑  
 Physical Infrastructure

As we move from **IaaS → PaaS → SaaS**, more responsibility shifts from the customer to the provider.
